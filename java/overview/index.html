    Java 개요¶

    ← Java로 돌아가기

    초보자를 위한 안내

    처음에는 소스 코드(.java)가 바이트코드(.class)로 컴파일된 뒤 JVM에서 실행된다는 전체 흐름만 익히면 충분합니다. JRE와 JDK의 구성 차이는 이런 것이 있다는 정도만 훑어보고, 개발환경 설정에서 직접 설치해 본 뒤 다시 읽으면 훨씬 쉽게 이해됩니다.

    Java는 JVM 위에서 실행되는 정적 타입 객체지향 언어로, "한 번 작성하면, 어디서든 실행된다"를 지향하며, 이 문서에서는 소스 코드가 실행되기까지의 과정과 JVM, JDK, JRE의 관계를 다룹니다.

    1. Java 실행 구조란¶

    소스 코드를 한 번 작성해두면, JVM이 설치된 어떤 운영체제에서도 같은 방식으로 실행할 수 있습니다. 이를 위해 소스 코드는 컴파일러를 거쳐 바이트코드로 변환되고, JVM이 이 바이트코드를 읽어 실행합니다.

    용어 설명
    소스 코드(.java) 개발자가 작성하는 Java 코드
    javac 소스 코드를 바이트코드로 변환하는 컴파일러
    바이트코드(.class) 운영체제에 종속되지 않는 중간 코드
    JVM 바이트코드를 해석·실행하는 가상 머신
    표준 라이브러리 자주 쓰는 기능을 미리 만들어 제공하는 라이브러리
    JRE JVM과 표준 라이브러리를 묶어 실행 환경만 제공하는 배포판
    JDK JRE에 javac 등 개발 도구를 더한 배포판
    • 전체 그림을 이해하려면 사람이 작성하는 소스 코드(.java), 이를 컴파일러가 변환한 바이트코드(.class), 바이트코드를 실제로 실행하는 JVM의 세 단계를 알아야 합니다.
    • 이 실행 환경을 배포 형태로 묶은 것이 JRE와 JDK입니다.

    2. javac의 바이트코드 변환¶

    Java 소스 코드는 사람이 읽고 쓰는 텍스트 형태의 .java 파일입니다. 이 상태로는 실행할 수 없고, javac 컴파일러가 이를 .class 확장자의 바이트코드로 변환해야 합니다. 이 변환 과정을 컴파일타임이라 부르고, 이후 JVM이 바이트코드를 읽어 실행하는 과정을 런타임이라 부릅니다.

    1
2
    javac Main.java    # 컴파일타임: Main.class 생성
java Main          # 런타임: JVM이 Main.class 실행
    용어 설명
    컴파일 사람이 작성한 소스 코드를 JVM이 실행할 수 있는 형태로 변환하는 과정
    컴파일타임 javac가 소스 코드를 바이트코드로 변환하는 시점
    런타임 JVM이 바이트코드를 읽어 실행하는 시점
    • 설치와 프로젝트 생성 및 실행은 개발환경 설정에서 다룹니다.

    컴파일 오류¶

    문법이 틀린 코드는 컴파일타임에 javac가 오류를 출력하며, 이 경우 .class 파일이 만들어지지 않아 실행할 수 없습니다.

    1
2
3
4
5
    public class Main {
    public static void main(String[] args) {
        System.out.println("Hello")
    }
}

    1
2
3
    Main.java:3: error: ';' expected
        System.out.println("Hello")
                                   ^
    • 컴파일 오류 메시지의 세부 표시는 javac 버전에 따라 다를 수 있습니다.

    실행 중 오류¶

    컴파일은 통과했지만 실행 중에 발생하는 오류는 런타임 예외라 합니다. 문법은 맞아도 실행 시점의 값이 잘못되면 JVM이 예외를 던지고 프로그램이 멈춥니다.

    1
2
3
4
5
6
    public class Main {
    public static void main(String[] args) {
        int[] numbers = new int[3];
        System.out.println(numbers[5]);
    }
}

    1
2
    Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 3
    at Main.main(Main.java:4)
    구분 발생 시점 결과
    컴파일 오류 javac 실행 시 .class 파일이 만들어지지 않음
    런타임 예외 java 실행 중 예외가 발생한 지점에서 프로그램이 멈춤
    • 존재하지 않는 클래스를 실행하면 Error: Could not find or load main class ...가 출력됩니다. 클래스 이름이나 실행 위치를 확인합니다.
    • 런타임 예외의 종류와 처리 방법은 예외 처리에서 자세히 다룹니다.

    javap로 바이트코드 확인¶

    javap는 JDK에 포함된 도구로, .class 파일에 담긴 바이트코드를 사람이 읽을 수 있는 형태로 보여줍니다. -c 옵션을 붙이면 메서드의 명령어까지 출력합니다.

2
    javac Main.java
javap -c Main

    • 상수 풀 번호(#7, #13)와 출력 형식은 JDK 버전에 따라 다를 수 있습니다.

    3. 바이트코드의 플랫폼 독립성¶

    바이트코드는 특정 CPU나 운영체제를 겨냥한 기계어가 아니라, JVM만이 이해하는 중간 형태의 코드입니다. 이 덕분에 같은 .class 파일을 운영체제 어디서든 JVM만 있으면 그대로 실행할 수 있습니다.

    용어 설명
    CPU 명령어를 실제로 읽고 계산하고 처리하는 중앙 처리 장치
    운영체제 CPU와 하드웨어 자원을 관리하며 프로그램 실행 환경을 제공하는 소프트웨어 (Windows, Linux, macOS 등)

    4. JVM의 바이트코드 실행¶

    JVM(Java Virtual Machine)은 바이트코드를 읽어 각 운영체제에 맞는 명령으로 해석·실행하는 소프트웨어입니다. 프로그램 실행에 필요한 메모리 공간을 마련하고, 더 이상 사용하지 않는 데이터를 자동으로 정리해 메모리를 관리하는 일도 JVM이 담당합니다.

    용어 설명
    메모리 프로그램이 실행되는 동안 데이터를 저장해두는 공간
    • JVM의 내부 구조는 JVM에서 자세히 다룹니다.

    5. JDK와 JRE의 구성¶

    JRE(Java Runtime Environment)는 JVM과 표준 라이브러리를 묶어 바이트코드를 실행만 할 수 있게 제공하는 배포판입니다. JDK(Java Development Kit)는 여기에 javac 같은 컴파일러와 개발 도구를 더해, 코드를 작성하고 컴파일까지 할 수 있게 해줍니다.

    • 설치 방법은 개발환경 설정에서 다룹니다.
