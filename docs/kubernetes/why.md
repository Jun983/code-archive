# 쿠버네티스를 사용하는 이유

[← Kubernetes로 돌아가기](index.md)

프로그램을 어디서든 똑같이 실행할 수 있도록 상자처럼 담아둔 것을 컨테이너라고 부릅니다. 컨테이너 하나만 실행한다면 크게 신경 쓸 일이 없습니다. 하지만 서비스가 커져서 컨테이너가 수십, 수백 개로 늘어나면 이야기가 달라집니다. 어떤 컨테이너가 죽었는지 계속 지켜봐야 하고, 트래픽이 몰릴 때마다 직접 늘리고 줄여야 하고, 컨테이너 위치가 바뀔 때마다 접속 정보를 다시 알려줘야 합니다. 이 모든 걸 사람이 손으로 하기는 어렵습니다. 쿠버네티스는 이런 반복 작업을 대신해주는 도구입니다.

| 상황 | 사람이 직접 관리할 때 | 쿠버네티스를 사용할 때 |
|---|---|---|
| 컨테이너에 문제가 생겼을 때 | 직접 확인하고 다시 실행 | 자동으로 감지 후 재실행 |
| 트래픽이 몰리거나 줄었을 때 | 직접 컨테이너 수 조절 | 사용량에 맞춰 자동 조절 |
| 컨테이너 위치가 바뀌었을 때 | 접속 정보를 직접 갱신 | 고정된 창구로 자동 연결 |

---

## 문제가 생긴 컨테이너를 알아서 다시 살립니다

컨테이너가 하나뿐이라면 문제가 생겼을 때 눈치채고 직접 다시 실행하면 됩니다. 하지만 컨테이너가 수십 개라면 어떤 게 죽었는지 계속 확인하고 있을 수 없습니다. 직원이 한 명뿐인 가게라면 결근을 바로 알아채지만, 직원이 백 명이라면 누가 안 나왔는지 일일이 확인하기 어려운 것과 같습니다.

→ **쿠버네티스는 컨테이너 상태를 계속 지켜보다가, 멈추거나 응답하지 않는 컨테이너를 자동으로 다시 실행합니다.** 컨테이너가 돌아가던 서버 자체에 문제가 생겨도, 다른 서버에서 대신 실행해줍니다.

## 사용량에 맞춰 컨테이너 수를 알아서 조절합니다

트래픽이 갑자기 몰리면 컨테이너를 더 띄워야 하고, 트래픽이 줄면 다시 줄여야 자원을 낭비하지 않습니다. 이걸 사람이 직접 지켜보다가 그때그때 늘리고 줄이는 건 현실적으로 불가능합니다. 손님이 몰리면 직원을 더 부르고, 한산해지면 다시 돌려보내는 일을 매장마다 사람이 실시간으로 판단해야 한다고 생각하면 얼마나 번거로운 일인지 알 수 있습니다.

→ **쿠버네티스는 사용량을 계속 확인하면서 컨테이너 수를 자동으로 늘리거나 줄여줍니다.** 필요하면 컨테이너를 실행할 서버 자체를 늘리는 것도 자동으로 처리할 수 있습니다.

## 컨테이너 위치가 바뀌어도 항상 같은 곳으로 접속할 수 있습니다

컨테이너는 다시 실행될 때마다 접속 정보가 바뀔 수 있습니다. 컨테이너가 몇 개 없다면 바뀐 정보를 직접 확인해서 알려줘도 되지만, 컨테이너가 많고 자주 재실행된다면 매번 추적하기 어렵습니다. 매장 안내 데스크가 없다면 손님이 지금 어느 직원이 비어 있는지 직접 찾아다녀야 하는 것과 비슷합니다.

→ **쿠버네티스는 컨테이너 앞에 고정된 접속 창구를 하나 만들어두고, 실제 요청이 오면 지금 살아있는 컨테이너로 알아서 연결해줍니다.** 컨테이너가 어디서 실행되고 있는지 신경 쓰지 않아도 항상 같은 곳으로 접속할 수 있습니다.
