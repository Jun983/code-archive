# HPA와 자동 확장

[← Kubernetes로 돌아가기](index.md)

[쿠버네티스를 사용하는 이유](why.md)에서 살펴본 것처럼, 트래픽이 몰리거나 줄어들 때마다 사람이 직접 Pod 수를 조절하는 건 현실적이지 않습니다. HPA(HorizontalPodAutoscaler)는 [ReplicaSet과 Pod 복제](replicaset.md)에서 다룬 Replicas 값을 지표에 따라 자동으로 조절해주는 리소스입니다. 이 문서에서는 세 가지, 지표 기반 판단·Replicas 조정·최소·최대 범위를 하나씩 살펴봅니다.

| 개념 | 설명 |
|---|---|
| 지표 기반 판단 | CPU 사용률 등 지표를 주기적으로 확인해 Pod를 늘릴지 줄일지 판단하는 것 |
| Replicas 조정 | 판단 결과에 따라 대상 리소스의 Replicas 값을 자동으로 바꾸는 것 |
| 최소·최대 범위 | Pod 수가 특정 범위를 벗어나지 않도록 상한과 하한을 두는 것 |

---

## 지표 기반 판단은 CPU 사용률 등을 기준으로 삼습니다

HPA는 대상 Pod들의 CPU 사용률 같은 지표를 주기적으로 확인합니다. 예를 들어 목표 CPU 사용률을 50%로 정해두면, 실제 평균 사용률이 이보다 높아졌을 때 트래픽이 몰려 자원이 부족해졌다고 판단하고, 반대로 낮아지면 여유가 생겼다고 판단합니다. CPU 사용률 외에 메모리 사용률이나 초당 요청 수 같은 다른 지표를 기준으로 삼을 수도 있습니다.

→ **HPA는 CPU 사용률 등 지표를 주기적으로 확인해, Pod를 늘려야 할지 줄여야 할지 판단합니다.**

## Replicas 조정은 판단 결과를 실제 Pod 수에 반영합니다

지표를 확인해 자원이 부족하거나 남는다고 판단하면, HPA는 [Deployment](deployment.md)나 ReplicaSet의 Replicas 값을 직접 늘리거나 줄입니다. 이때 HPA가 Pod를 직접 만들거나 지우는 것이 아니라, Replicas 값만 바꿔주면 나머지는 [Replicas](replicaset.md)에서 다룬 컨트롤 루프가 그 값에 맞춰 Pod 수를 실제로 맞춥니다. 즉 HPA는 "몇 개가 필요한지"를 계산하는 역할만 맡고, 실제로 Pod를 만들고 지우는 일은 기존 컨트롤 루프에 맡깁니다.

→ **HPA는 판단 결과에 따라 Replicas 값을 자동으로 조정하며, 실제 Pod 생성·삭제는 기존 컨트롤 루프가 처리합니다.**

## 최소·최대 범위는 Pod 수가 지나치게 늘거나 줄지 않도록 막습니다

HPA를 설정할 때는 Pod 수의 최소값과 최대값을 함께 지정합니다. 트래픽이 완전히 없어져도 최소값 아래로는 줄어들지 않아 서비스가 완전히 끊기는 상황을 막고, 트래픽이 지나치게 몰려도 최대값을 넘어서지 않아 클러스터 자원을 모두 소진하거나 예상치 못한 비용이 발생하는 상황을 막습니다.

→ **HPA는 최소·최대 범위 안에서만 Pod 수를 조절해, 서비스 중단과 자원 과다 사용을 동시에 방지합니다.**

## 세 요소는 함께 자동 확장을 만듭니다

HPA는 지표를 기준으로 판단하고, 그 판단을 Replicas 값에 반영하며, 이 조정이 정해둔 최소·최대 범위 안에서만 이루어지도록 하는 세 요소가 맞물려 동작합니다. 그 결과 사람이 트래픽을 지켜보며 직접 Pod 수를 조절하지 않아도, 사용량에 맞춰 자동으로 늘고 줄어드는 서비스를 만들 수 있습니다.

→ **HPA는 지표 기반 판단·Replicas 조정·최소·최대 범위를 통해, 트래픽 변화에 따라 Pod 수를 자동으로 조절하는 리소스입니다.**
