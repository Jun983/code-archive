# Volume과 데이터 저장 방식

[← Kubernetes로 돌아가기](index.md)

[파드와 그 구성 요소](pod.md)에서 살펴본 것처럼 Pod는 언제든 삭제되고 새로 만들어집니다. 이때 Container 안에 저장된 데이터도 Pod와 함께 사라지는데, Volume은 이 데이터를 Pod 생명주기와 분리해서 보관하기 위한 저장 공간입니다. 이 문서에서는 세 가지 방식, emptyDir·hostPath·PV/PVC를 하나씩 살펴봅니다.

| 방식 | 설명 |
|---|---|
| emptyDir | Pod가 살아있는 동안만 유지되는 임시 저장 공간 |
| hostPath | Pod가 배치된 Node의 특정 경로를 그대로 사용하는 방식 |
| PV/PVC | 외부 스토리지 기반의 영구 저장 공간을 뜻하는 PV와, 그 사용 요청을 뜻하는 PVC |

---

## emptyDir는 Pod가 살아있는 동안만 유지되는 임시 공간입니다

emptyDir는 Pod가 생성될 때 함께 만들어지는 빈 디렉터리입니다. 같은 Pod 안의 여러 Container가 [파드와 그 구성 요소](pod.md)에서 설명한 것처럼 저장 공간을 공유한다는 특성을 이용해, 이 emptyDir를 통해 Container끼리 파일을 주고받을 수 있습니다.

다만 emptyDir의 생명주기는 Pod와 정확히 같습니다. Pod 안의 Container가 재시작되어도 emptyDir의 데이터는 유지되지만, Pod 자체가 삭제되면 emptyDir도 함께 사라집니다. 그래서 로그 임시 저장이나 Container 간 파일 공유처럼, Pod가 사라지면 함께 없어져도 되는 데이터에 주로 사용합니다.

→ **emptyDir는 Pod 생명주기에 종속된 임시 저장 공간이며, 같은 Pod 안 Container끼리 데이터를 주고받을 때 사용합니다.**

## hostPath는 Node의 특정 경로를 그대로 사용합니다

hostPath는 Pod가 배치된 Node의 파일 시스템 경로를 Container에 그대로 연결하는 방식입니다. emptyDir와 달리 Pod가 삭제되어도 데이터는 Node에 남아있기 때문에, 같은 Node에 다시 Pod가 배치되면 이전 데이터를 이어서 사용할 수 있습니다.

하지만 이 데이터는 특정 Node에 묶여 있습니다. [스케줄링](pod.md)에 의해 Pod가 다른 Node로 옮겨가면 그 Node에는 같은 데이터가 없기 때문에, 여러 Node에 걸쳐 실행되는 애플리케이션에는 적합하지 않습니다. 그래서 Node의 로그를 수집하거나 Node 자체의 설정 파일에 접근해야 하는 것처럼, 특정 Node와 밀접한 작업에 제한적으로 사용합니다.

또한 hostPath는 Container가 Node의 파일 시스템에 직접 접근하는 방식이라, Node의 민감한 파일이나 다른 애플리케이션의 데이터까지 건드릴 수 있어 보안상 위험할 수 있습니다. 그래서 꼭 필요한 경우가 아니면 잘 사용하지 않고, 뒤에서 설명할 PV/PVC를 우선 고려하는 것이 일반적입니다.

→ **hostPath는 Pod가 아닌 Node에 데이터를 저장하는 방식이며, 특정 Node에 종속된 작업에만 제한적으로 사용합니다.**

## PV는 저장 공간을, PVC는 그에 대한 요청을 나타냅니다

emptyDir와 hostPath는 각각 Pod나 Node에 데이터가 묶여 있어, Pod가 삭제되거나 다른 Node로 옮겨가면 데이터를 잃거나 이어받지 못합니다. PV(PersistentVolume)는 이 문제를 해결하기 위한 저장 공간입니다. NFS나 클라우드 디스크(AWS EBS 등) 같은 실제 외부 스토리지를 기반으로 만들어지며, 보통 관리자가 미리 만들어두거나 StorageClass(스토리지 설정을 미리 정의해둔 템플릿)를 통해 필요할 때 자동으로 생성됩니다.

PVC(PersistentVolumeClaim)는 이 PV를 사용하겠다는 요청서 역할을 합니다. Pod는 PV를 직접 다루지 않고, PVC를 통해 필요한 용량과 조건(예: 접근 모드)을 명시해 원하는 PV를 할당받습니다. 이렇게 요청과 실제 저장 공간을 분리해두면, Pod가 삭제되거나 다른 Node로 옮겨가도 같은 PVC를 통해 동일한 PV에 다시 연결할 수 있습니다. 또한 PVC와 PV는 Pod보다 생명주기가 길어서, Pod가 삭제되어도 특별히 지우지 않는 한 그대로 남아있습니다.

이 방식은 데이터베이스처럼 Pod가 사라져도 데이터는 반드시 유지되어야 하는 애플리케이션에 사용합니다.

→ **PV는 외부 스토리지 기반 저장 공간, PVC는 그에 대한 요청이며, 분리해두면 Pod나 Node의 생명주기와 무관하게 데이터를 유지할 수 있습니다.**
