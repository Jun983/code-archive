# StatefulSet과 상태 저장 워크로드

[← Kubernetes로 돌아가기](index.md)

[ReplicaSet과 Pod 복제](replicaset.md), [Deployment와 배포 전략](deployment.md) 등이 관리하는 Pod들은 서로 완전히 동등합니다. 어떤 Pod가 죽어도 다른 Pod와 구분 없이 새 Pod로 대체되면 그만입니다. 하지만 데이터베이스처럼 각 Pod가 자신만의 데이터를 갖고, 그 정체성이 유지되어야 하는 워크로드도 있습니다. StatefulSet은 이런 "각 Pod가 서로 구분되어야 하는" 상태 저장 워크로드를 위한 Controller입니다. 이 문서에서는 세 가지, 고정 식별자·순차적 생성과 삭제·[Volume](volume.md) 연결을 하나씩 살펴봅니다.

| 개념 | 설명 |
|---|---|
| 고정 식별자 | Pod마다 순번이 붙은 이름과 네트워크 주소가 재생성 후에도 유지되는 것 |
| 순차적 생성과 삭제 | Pod를 0번부터 순서대로 만들고, 역순으로 지우는 것 |
| Volume 연결 | 각 Pod가 자신만의 PVC를 독립적으로 갖고 재사용하는 것 |

---

## 고정 식별자는 Pod가 재생성되어도 이름과 주소를 유지합니다

[ReplicaSet](replicaset.md)이 관리하는 Pod는 이름이 무작위 문자열로 붙고, 죽었다 다시 만들어지면 이름과 IP가 모두 바뀝니다. 반면 StatefulSet이 관리하는 Pod는 `web-0`, `web-1`, `web-2`처럼 순번이 붙은 이름을 갖고, 이 Pod가 삭제된 뒤 다시 만들어져도 항상 같은 이름을 다시 받습니다.

이 고정된 이름은 클러스터 내부 네트워크 주소로도 그대로 이어져서, 다른 Pod가 `web-0`을 찾을 때 IP가 바뀌었는지 신경 쓸 필요 없이 항상 같은 이름으로 접근할 수 있습니다. 여러 대의 데이터베이스 노드 중 어느 것이 대표(primary) 노드인지처럼, "몇 번째 Pod인지"가 역할과 직결되는 경우에 특히 중요합니다.

→ **StatefulSet이 관리하는 Pod는 재생성되어도 순번이 붙은 이름과 네트워크 주소를 그대로 유지합니다.**

## 순차적 생성과 삭제는 Pod의 시작·종료 순서를 보장합니다

[ReplicaSet](replicaset.md)은 Replicas 수만큼 Pod를 한꺼번에 만들지만, StatefulSet은 `web-0`이 준비 상태가 될 때까지 기다린 뒤에야 `web-1`을 만들기 시작하는 식으로 하나씩 순서대로 Pod를 만듭니다. 삭제할 때도 반대로 가장 번호가 큰 Pod부터 하나씩 지워나갑니다.

이런 순서 보장은 데이터베이스 클러스터처럼 노드마다 시작 순서가 의미를 갖는 경우에 필요합니다. 예를 들어 대표 노드가 먼저 뜨고 나머지 노드가 그 뒤를 따라야 하는 구조라면, 순서 없이 한꺼번에 Pod가 뜰 때 발생할 수 있는 문제를 피할 수 있습니다.

→ **StatefulSet은 Pod를 번호 순서대로 하나씩 만들고 역순으로 하나씩 지우며, 시작·종료 순서가 중요한 워크로드에 적합합니다.**

## 각 Pod는 자신만의 Volume을 독립적으로 갖습니다

[Volume과 데이터 저장 방식](volume.md)에서 살펴본 PVC를 여러 Pod가 공유하도록 [Deployment](deployment.md)에 연결하면, 모든 Pod가 같은 저장 공간을 함께 쓰게 됩니다. 하지만 StatefulSet은 Pod마다 별도의 PVC를 자동으로 하나씩 만들어 연결해서, `web-0`은 `web-0`의 데이터만, `web-1`은 `web-1`의 데이터만 사용하도록 분리합니다.

이 PVC는 Pod의 생명주기와 분리되어 있어, `web-0`이 삭제되었다가 같은 이름으로 다시 만들어지면 이전에 쓰던 PVC를 그대로 다시 연결받습니다. 즉 Pod는 새로 만들어져도 그 Pod가 쓰던 데이터는 그대로 이어집니다.

→ **StatefulSet은 Pod마다 독립된 PVC를 만들어 연결하며, Pod가 재생성되어도 같은 번호의 Pod는 이전 데이터를 그대로 이어받습니다.**

## 세 특성은 함께 Pod의 정체성을 유지합니다

고정 식별자, 순차적 생성과 삭제, 독립된 Volume은 모두 같은 목적을 향합니다. Pod 하나하나가 대체 가능한 존재가 아니라, 이름·순서·데이터를 가진 고유한 존재로 다뤄지도록 만드는 것입니다. 그래서 StatefulSet은 무상태 웹 서버보다는 데이터베이스, 메시지 큐처럼 노드 간 정체성과 데이터가 중요한 워크로드에 사용합니다.

→ **StatefulSet은 고정 식별자·순차적 생성과 삭제·독립된 Volume을 통해 각 Pod의 정체성을 유지하는 Controller입니다.**
