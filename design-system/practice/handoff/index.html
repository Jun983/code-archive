    개발 전달 산출물 정리 실습¶

    ← 디자인 시스템으로 돌아가기

    앞선 실습의 토큰 파일과 my-ui 패키지를 handoff 폴더 한 곳에 모으고, 사용 가이드를 작성한 뒤 전달 체크리스트를 실행합니다. 마지막으로 토큰 값 하나를 바꿔 버전과 변경 이력을 갱신하며 되돌아가기 흐름을 한 번 경험합니다. 개념 설명은 개발 전달 산출물 정리에 있으므로 이 문서에서는 반복하지 않고 작업 순서와 확인 방법만 둡니다.

    구분 내용
    입력 토큰 실습의 tokens/tokens.json, build/css/variables.css와 컴포넌트 라이브러리 실습의 my-ui 프로젝트
    산출물 handoff 폴더(토큰 파일, 패키지 .tgz), my-ui/README.md(사용 가이드), my-ui/CHANGELOG.md, 갱신된 버전 0.1.1
    다음 단계 없음. 이 실습이 실습편의 마지막 단계입니다.

    실제 전달 대상(백엔드)이 선호하는 전달 형식은 확인하지 못했으므로 이 실습은 .tgz 패키지 파일과 토큰 파일 묶음을 전달하는 것으로 가정하며, 형식이 정해지면 handoff 폴더 구성만 바꿉니다.

    실습 범위와 환경¶

    범위¶

    항목 이 실습에서 하는 일
    산출물 모으기 토큰 파일과 패키지를 handoff 폴더로 모음
    사용 가이드 my-ui/README.md를 개념 문서의 세 부분에 맞춰 작성
    체크리스트 개념 문서의 산출물 누락 확인 항목을 명령어로 실행
    변경 이력 토큰 값 하나를 바꿔 버전을 올리고 CHANGELOG.md에 기록

    배포 레지스트리에 올리는 일은 하지 않습니다. 레지스트리와 카탈로그 호스팅 위치는 개념 문서에서 아직 정해지지 않은 항목입니다.

    환경¶

    컴포넌트 라이브러리 실습의 환경과 같습니다. 이 문서의 명령어 출력은 Node.js 22.22.2, npm 10.9.7에서 직접 실행해 확인한 값입니다.

    이전 단계 완성 산출물¶

    앞 실습을 마치지 못했다면 아래 표에서 해당하는 행의 방법으로 입력을 준비합니다. 별도 압축 파일을 두지 않고 각 실습 문서에 실린 정답 코드를 쓰는 방식입니다.

    없는 입력 준비 방법
    tokens/tokens.json expected/tokens.json을 복사합니다. mkdir -p tokens && cp expected/tokens.json tokens/tokens.json (토큰 실습 2-2)
    build/css/variables.css node build-tokens.js를 실행하거나 3-3의 정답 CSS를 저장합니다.
    my-ui 프로젝트 컴포넌트 라이브러리 실습의 단계 코드를 1단계부터 5단계까지 따라 npm run build가 통과하는 상태로 만듭니다. 완성 폴더 구조와 대조합니다.

      # my-ui

React 컴포넌트 라이브러리입니다. 디자인 토큰(CSS 변수)과 컴포넌트를 함께 제공합니다.

## 설치

```bash
npm install my-ui
```

| 요구 환경 | 버전 |
|---|---|
| Node.js | 20.19.0 이상 또는 22.12.0 이상 |
| react, react-dom | 19 |

## 시작하기

토큰 CSS를 컴포넌트 CSS보다 먼저 불러옵니다. 컴포넌트 스타일이 토큰 변수를 참조하므로 순서가 바뀌면 색이 적용되지 않습니다.

```tsx
import 'my-ui/tokens.css';
import 'my-ui/style.css';
import { Button, Input } from 'my-ui';

export const App = () => (
  <>
    <Button>저장</Button>
    <Input placeholder="이름" invalid />
  </>
);
```

## props 규칙

Figma의 variant·property 이름이 props 이름과 같습니다. Figma에서 값을 가진 variant는 문자열 prop으로, 상태(`error` 등)는 불리언 prop으로 대응합니다.

## 테마 조정

`--color-blue-500` 같은 토큰 변수를 `:root` 뒤에서 덮어쓰면 값을 바꿀 수 있습니다. 토큰 파일(`variables.css`)은 직접 수정하지 않습니다.

```css
:root {
  --color-bg-primary-default: #2563eb;
}
```

## 컴포넌트 목록

| 컴포넌트 | 주요 props | 상태 |
|---|---|---|
| `Button` | `variant` (`'primary'`) | Primary |
| `Input` | `invalid` | Default, Invalid |

상태별 모습은 Storybook 카탈로그에서 확인합니다.

    2. 기대 결과: my-ui/README.md가 생기고 설치, 시작하기, props 규칙, 테마 조정, 컴포넌트 목록 다섯 절이 있습니다.

    3. 확인 방법: 가이드의 코드 예시는 6-1의 consumer/main.tsx와 같은 코드여야 합니다. 개념 문서의 "실제 빌드된 패키지에서 동작하는 것만 적는다"는 기준을 3단계에서 consumer로 확인합니다.

    컴포넌트 목록과 상태는 직접 늘리지 않습니다

    목록은 src/index.ts의 공개 export와 같은 항목만 적고, 상태별 모습은 카탈로그로 연결합니다. 목록을 두 곳에서 관리하면 어긋나므로, 컴포넌트가 늘어나면 이 표와 src/index.ts를 함께 고칩니다.

    막혔을 때¶

    증상 확인
    npm pack --pack-destination에서 handoff 폴더가 없다는 오류 1-1의 mkdir -p handoff/tokens를 실행했는지 확인합니다.
    패키지에 README.md나 CHANGELOG.md가 없음 my-ui/package.json의 files에 두 파일이 있는지 확인하고 npm pack을 다시 실행합니다.
    dist/variables.css가 패키지 목록에 없음 npm run build를 하지 않고 npm pack을 실행한 것입니다. npm run build의 cp가 이 파일을 dist로 복사합니다.
    consumer가 새 값을 못 받음 consumer/package.json의 my-ui 경로가 새 .tgz인지 확인하고 rm -rf node_modules/my-ui 뒤 다시 설치합니다.
    comm -23에 토큰 이름이 출력됨 컴포넌트 CSS가 참조하는데 variables.css에 없는 토큰입니다. 토큰 실습의 변환 결과와 이름을 대조합니다.
    3-1에서 diff가 출력됨 my-ui/src/tokens/variables.css 또는 handoff/tokens/variables.css가 오래된 복사본입니다. 최신 build/css/variables.css를 복사합니다.

    실습 완료 확인¶

    • handoff 폴더에 tokens/tokens.json, tokens/variables.css, my-ui-0.1.1.tgz가 있다.
    • my-ui/README.md에 설치, 시작하기, props 규칙, 테마 조정, 컴포넌트 목록이 있고 토큰 CSS를 먼저 불러오라는 안내가 있다.
    • 3단계의 체크리스트 명령이 모두 기대 결과와 같다(SAME, 공개 export 2개, comm -23 출력 없음).
    • consumer에서 handoff의 패키지로 설치해 타입 검사와 빌드가 된다.
    • 토큰 값 하나를 바꿔 package.json의 version이 0.1.1이 되고 CHANGELOG.md에 토큰 변경이 기록되었다.
    • 새 패키지로 빌드한 consumer CSS에 #2563eb만 있고 #3b82f6은 없다.
