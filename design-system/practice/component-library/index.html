    React 컴포넌트 라이브러리 구축 실습¶

    ← 디자인 시스템으로 돌아가기

    디자인 토큰 추출·발행 실습에서 만든 variables.css를 사용하는 Button, Input 컴포넌트를 만들고, 라이브러리로 빌드한 뒤 Storybook 카탈로그에서 확인합니다. 개념 설명은 React 컴포넌트 라이브러리 구축에 있으므로 이 문서에서는 반복하지 않고 작업 순서와 확인 방법만 둡니다.

    구분 내용
    입력 디자인 토큰 추출·발행 실습의 build/css/variables.css
    산출물 my-ui 프로젝트(Button, Input 컴포넌트, 빌드 결과 dist, Storybook 카탈로그)
    다음 단계 컴포넌트와 토큰이 개발 전달 산출물 정리 실습의 입력이 됩니다.

    제안임을 밝힙니다

    도구 조합(React, TypeScript, Vite, vite-plugin-dts, Storybook)과 폴더 구조는 개념 문서의 도구 선정 (제안)을 그대로 따른 제안입니다. 팀의 기존 스택이 있으면 그 스택을 우선하고, 이 실습은 흐름을 익히는 용도로 씁니다.

    실습 범위와 환경¶

    범위¶

    모든 컴포넌트를 만들지 않고 샘플 Figma 파일에 있는 Button, Input 두 개로 제한합니다. 샘플 파일에 없는 속성은 만들지 않는다는 대응 기준에 따라 아래와 같이 정합니다.

    컴포넌트 Figma 명세 이 실습의 props
    Button variant 없음(기본 스타일 하나) variant?: 'primary'. 값이 하나뿐이지만 샘플 Figma에 variant가 추가될 때 값만 늘리도록 prop은 둡니다.
    Input State variant: default, focus, error default, focus는 CSS(:focus-visible), error는 invalid prop
    • 시작 코드: 1단계를 마친 상태(프로젝트 폴더, 설정 파일, 토큰 파일)입니다. 2단계 이후가 막히면 1단계 결과로 돌아와 다시 진행합니다.
    • 완성 코드: 각 단계에 실린 코드 전체입니다. 막혔을 때의 완성 폴더 구조와 대조합니다.
    • 카탈로그 배포: 이 실습의 범위에 넣지 않습니다. 7단계에서 정적 파일로 빌드하는 데까지만 합니다. 배포 위치는 카탈로그 배포를 따라 조직 사정에 맞춰 정합니다.

    환경¶

    변환 결과와 명령어 출력은 아래 버전으로 직접 실행해 확인한 값입니다.

    도구 버전 비고
    Node.js 22.22.2 Vite 8.3.8은 ^20.19.0 \|\| >=22.12.0 필요
    react, react-dom 19.3.1
    typescript 6.0.3 7.0.2는 쓰지 않음(아래 경고 참고)
    vite 8.3.8
    @vitejs/plugin-react 6.3.0
    vite-plugin-dts 5.1.2
    storybook, @storybook/react-vite 10.6.8

    TypeScript 7은 이 조합에서 빌드되지 않습니다

    TypeScript 7.0.2를 설치하면 vite build가 The installed "typescript" package does not provide the JavaScript Compiler API 오류로 멈춥니다. vite-plugin-dts가 TypeScript의 JavaScript API를 쓰기 때문입니다. 이 실습은 6.0.3으로 고정합니다.

    설치 시간은 이 환경에서 패키지 설치(npm install)가 각각 5초 안팎이었고 Storybook 카탈로그 빌드가 3초 안팎이었습니다. 네트워크 속도에 따라 달라지므로 수업 시간에는 설치 단계를 미리 끝내 두는 것을 권장합니다.

    2. Button 구현¶

    2-1. 토큰을 참조하는 스타일¶

    토큰 적용 원칙에 따라 색상·간격·반경은 의미 기반 토큰(--color-bg-primary-default)만 참조합니다. 원시 토큰(--color-blue-500)은 쓰지 않습니다.

    1. 작업: my-ui 폴더 기준으로 src/components/Button/Button.css를 만들고 아래 내용을 저장합니다.

    3. 확인 방법: 색상·간격·반경이 모두 var(--...)로만 쓰였는지 확인합니다.

    토큰이 아닌 값 예외

    font-size: 14px, font-weight: 500은 토큰이 아닌 값입니다. 샘플 Figma의 글자 크기·굵기(Inter Medium 14)는 텍스트 스타일이고 토큰 실습의 발행 대상(변수 20개)에 없기 때문입니다. 원칙대로라면 토큰 쪽에 추가를 요청할 항목이며, 이 실습에서는 예외로 두고 직접 씁니다. cursor: pointer처럼 토큰화 대상이 아닌 값도 같습니다.

export interface ButtonProps
  extends React.ButtonHTMLAttributes<HTMLButtonElement> {
  /** 버튼 스타일. 샘플 Figma 파일에는 primary 하나만 있다. */

  const classes = ['btn', `btn--${variant}`, className].filter(Boolean).join(' ');
  return <button className={classes} {...rest} />;
}

export interface InputProps
  extends React.InputHTMLAttributes<HTMLInputElement> {

  invalid?: boolean;

export function Input({ invalid = false, className, ...rest }: InputProps) {
  const classes = ['input', invalid && 'input--invalid', className]

  return <input className={classes} aria-invalid={invalid || undefined} {...rest} />;

    막혔을 때¶

    증상 확인
    vite build가 does not provide the JavaScript Compiler API로 멈춤 npm ls typescript로 버전이 6.0.3인지 확인합니다. 7.x이면 npm install --save-dev typescript@6.0.3으로 되돌립니다.
    컴포넌트에서 import './Button.css'에 TS2882 오류 tsconfig.json의 types에 vite/client가 있는지 확인합니다.
    카탈로그에서 색이 모두 빠지고 회색·검정으로만 보임 .storybook/preview.ts의 토큰 import 경로를 확인합니다.
    cp: ../build/css/variables.css: No such file or directory 토큰 실습 3단계가 끝나지 않은 것입니다. 급하면 3-3의 정답 CSS를 src/tokens/variables.css로 저장합니다.
    Cannot find module 'my-ui' consumer에서 npm install ../my-ui/my-ui-0.1.0.tgz를 다시 실행합니다. npm pack이 빌드 전에 실행되어 dist가 비어 있었다면 npm run build 후 npm pack을 다시 합니다.
    단계 코드가 어긋나 원인을 못 찾음 시작 코드 상태(1단계 끝)로 돌아가 단계 코드를 처음부터 다시 붙여 넣습니다. 완성 폴더 구조와 파일 이름을 대조합니다.

    실습 완료 확인¶

    • 컴포넌트 CSS의 색상·간격·반경이 모두 var(--...)로만 쓰였다(예외는 2-1에 적은 글자 크기·굵기·width뿐).
    • Button의 variant, Input의 invalid prop이 Figma 명세와 같은 이름·값이다.
